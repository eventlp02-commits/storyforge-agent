# 通用短剧创作大师 v2.0 PRD

## 1. 文档信息

- 产品名称：通用短剧创作大师
- 版本：2.0
- 核心能力：基于真实生成结果逐段续写的视频创作 Skill
- 文档状态：已确认，进入重构
- 更新日期：2026-07-28

## 2. 背景

旧版工作流先把整段故事、全局时间线和全部视频提示词一次性写完。这种做法适合纸面分镜，不适合存在生成偏差的视频模型。实际成片可能提前完成动作、改变人物站位、偏移机位、停在意外表情或丢失预定转场。后续提示词如果仍从纸面计划出发，就会出现动作重复、空间跳变、角色瞬移和情绪断裂。

旧版还把内部资产编号、文件名和制作说明写进可复制提示词，用户复制到模型后会夹带无效信息。全局累计时间码也不符合逐段生成的操作方式。

v2.0 将工作单元从“完整影片”改为“一个可验证的 Clip”。系统只制作当前 Clip，检查它实际生成到哪里，再从真实结尾继续下一段。

## 3. 问题定义

必须解决以下问题：

1. 不得在看到 Clip 01 实际结果前编写 Clip 02 的可执行提示词。
2. 每个 Clip 必须使用自己的局部时间轴，并从 0 秒开始。
3. 生成提示词不得出现内部资产编号、文件名、路径或制作说明。
4. 生成提示词不得出现面向用户的解释、免责声明、工作状态和复制说明。
5. 镜头设计不能只更换景别而重复同一动作。
6. 每个 Clip 必须有明确的戏剧任务、镜头表达、光线任务和声音任务。
7. 下一段必须继承上一段真实末帧中的人物、动作、机位、光线、环境和声音状态。
8. 自动校验必须能阻止累计时间码、脏提示词和未检查结果就续写的行为。

## 4. 产品目标

### 4.1 核心目标

- 建立“创作当前段、生成当前段、检查真实结果、续写下一段”的闭环。
- 输出可以直接粘贴到视频模型的纯净提示词。
- 保留完整故事的创作方向，但不提前冻结未来 Clip 的动作和时间细节。
- 用导演思维控制每段的戏剧作用、摄影、光线和声音。
- 让连续动作、空间关系、情绪和视听状态可追踪、可验证。

### 4.2 成功指标

- 所有 Clip 的第一个时间码为 0 秒。
- 所有 Clip 内部时间区间连续，最后一个时间码等于本段时长。
- 提示词中技术文件名和内部资产 ID 出现次数为 0。
- 提示词中制作解释和工作流说明出现次数为 0。
- 未提供上一段实际结果时，下一段可执行提示词生成次数为 0。
- 续写 Clip 的开场状态与上一段实际末帧状态匹配。
- 同一连续动作不会在相邻 Clip 中无理由重置或重复。

## 5. 非目标

- v2.0 不保证视频模型严格执行所有动作。
- v2.0 不提前生成整部影片的全部可执行提示词。
- v2.0 不把完整非线性剪辑器纳入 Skill。
- v2.0 不用内部资产编号替代模型可识别的媒体引用。
- v2.0 不提供规避平台审核或隐藏受限内容的方法。
- v2.0 不把平台当前参数限制写死在通用规范中。

## 6. 用户与使用场景

### 6.1 目标用户

- 使用生成式视频模型制作连续剧情的创作者
- 需要 Word 剧本和可复制提示词的导演、编剧和分镜师
- 制作广告、MV、宣传片、短剧、预告片、教程或世界观视频的用户

### 6.2 典型场景

1. 用户提供一句创意，系统建立故事路线并只输出 Clip 01。
2. 用户上传 Clip 01 成片，系统检查真实结尾并输出 Clip 02。
3. 用户指出成片与提示词不一致，系统以成片为准修订连续性。
4. 用户提供角色图和场景图，系统在提示词中使用 `@图片1`、`@视频1` 等模型可识别引用。
5. 用户要求 Word 文档，系统分别提供制作文件与纯提示词文件，避免解释文字污染复制内容。

## 7. 核心原则

### 7.1 真实结果优先

成片事实高于剧本计划、分镜计划和上一版提示词。后续创作必须从真实画面和真实声音继续。

### 7.2 一次只制作一个 Clip

允许提前建立整部作品的非执行性故事路线，但可执行的视频提示词一次只生成一个 Clip。Clip N+1 必须等待 Clip N 的实际结果被检查和锁定。

### 7.3 导演四问

每次写 Clip 前必须完成内部导演判断：

1. 这场戏在做什么：转折、揭示、情绪、展示、冲突、证明或收束。
2. 镜头怎么把它说出来：景别、机位、镜头运动、阻挡关系和动作节奏如何服务任务。
3. 光帮什么忙：时辰、方向、软硬、冷暖、明暗变化如何服务情绪和信息。
4. 声音在做什么：环境声、同步动作声、对白、停顿、静默或音乐如何服务节奏。

四问答案属于内部导演卡，不进入可复制提示词文档，除非用户明确要求查看创作分析。

### 7.4 提示词纯净

可复制提示词只包含模型需要执行的视听指令。制作说明、文件说明、状态说明、引用解释、资产清单和对用户说的话必须放在其他文件。

### 7.5 局部时间

每个 Clip 都从 `0秒` 开始。Clip 01 可以是 `0-15秒`，Clip 02 仍然是 `0-15秒`。不得把 Clip 02 写成 `15-30秒`。

## 8. 术语

- Project：完整视频项目。
- Story Route：完整作品的高层故事路线，只描述顺序、冲突和目标，不包含未来 Clip 的可执行提示词。
- Clip：一次提交给视频模型的独立生成单元。
- Director Card：写 Clip 前的内部导演卡。
- Copy-ready Prompt：可直接粘贴到视频模型的纯提示词。
- Actual End State：从真实成片最后有效画面和声音中提取的结束状态。
- Continuity Lock：下一段必须继承的状态集合。

## 9. 用户流程

### 9.1 新项目

1. 解析题材、形式、目标时长、画幅、语言、风格和声音要求。
2. 形成高层 Story Route。
3. 建立 Clip 01 的 Director Card。
4. 编写并校验 Clip 01 的 Copy-ready Prompt。
5. 输出 Clip 01，状态进入 `waiting_for_result`。
6. 不创建 Clip 02 的 Copy-ready Prompt。

### 9.2 续写

1. 用户上传 Clip N 的实际视频或关键帧。
2. 读取真实时长、末段画面和可用声音信息。
3. 提取 Actual End State。
4. 标出计划与实际的差异。
5. 锁定人物、动作阶段、机位、构图、光线、环境、道具、特效和声音尾点。
6. 依据真实结果建立 Clip N+1 的 Director Card。
7. 编写并校验 Clip N+1 的 Copy-ready Prompt。
8. 输出后再次进入 `waiting_for_result`。

### 9.3 无法读取成片

如果没有 Clip N 的实际结果，或结果无法读取：

- 保留 Story Route。
- 保留当前 Clip 提示词。
- 状态停在 `waiting_for_result`。
- 不猜测 Actual End State。
- 不生成 Clip N+1 的可执行提示词。

## 10. Clip 状态机

```text
planned
  -> directing
  -> prompt_ready
  -> waiting_for_result
  -> inspecting
  -> end_locked
  -> completed
```

异常状态：

- `needs_revision`：提示词未通过校验或用户要求修改。
- `result_unreadable`：实际结果无法解析。
- `cancelled`：用户取消当前 Clip。

只有 Clip N 为 `end_locked` 或 `completed` 时，Clip N+1 才能进入 `directing`。

## 13. 可复制提示词合同

### 13.1 允许内容

- `@图片1`、`@视频1`、`@音频1` 等模型可识别引用
- 每个引用在画面中的用途
- 画面主体、场景、动作和动作进程
- 景别、机位、镜头运动和构图变化
- 光线、色彩、天气和环境反馈
- 对白、语言、声线、环境声、同步音效和音乐策略
- 本 Clip 的局部时间区间
- 与上段实际末帧一致的开场状态
- 具体且必要的失败规避指令

### 13.2 禁止内容

- `资产引用`
- `Asset calls`
- `prompt-only`
- 内部资产 ID，如 `REF-001`、`CHR-001`、`LOC-001`
- 文件名或路径，如 `.png`、`.jpg`、`.mp4`、`.wav`、`.docx`
- “直接使用用户图 1”
- “直接引用某文件”
- “上图只是……”
- “以下正文保留……”
- “实际生成时必须……”
- “这是给你的说明……”
- 交付状态、工作流解释、复制说明和面向用户的备注
- 全局累计时间码
- 尚未被真实成片确认的未来 Clip 提示词

### 13.3 引用写法

合格：

```text
以@视频1最后一帧为开场，保持人物站位、身体朝向、机位高度和冷暖光关系不变。@图片1用于锁定主角外观，@图片2用于锁定场景结构。
```

不合格：

```text
直接引用 REF-001_main-character.png，prompt-only。
```

### 13.4 时间写法

15 秒 Clip：

```text
0-3秒：
3-7秒：
7-11秒：
11-15秒：
```

下一段仍然从 0 开始：

```text
0-4秒：
4-9秒：
9-15秒：
```

## 14. Word 与文件输出

### 14.1 双文件策略

制作型项目默认分为：

1. 制作文件：剧本、Story Route、导演卡、真实末帧记录和质检结果。
2. 纯提示词文件：只包含 Copy-ready Prompt。

用户提供 Word 模板时，保持模板结构，但纯提示词区域仍不得混入解释性文字。

### 14.2 单段交付

每次只更新当前 Clip：

```text
03_clips/
  CLIP-01/
    director_card.json
    prompt.txt
    result/
    actual_end_state.json
```

只有 `actual_end_state.json` 完成后，才能创建下一个 Clip 目录中的可执行提示词。

## 15. 内部资产与模型引用

内部资产清单可以继续用于管理角色、场景、道具和生成结果，但不得进入 Copy-ready Prompt。

模型提示词仅使用模型能理解的顺序引用：

- `@图片1`
- `@图片2`
- `@视频1`
- `@音频1`

内部系统负责维护“上传顺序与内部资产”的映射。用户复制的提示词不暴露内部文件名。

## 16. 自动校验

### 16.1 时间校验

- 每个 Clip 第一段必须从 0 开始。
- Clip 内时间区间必须连续且不重叠。
- Clip 最后时间必须等于 `clip_duration_seconds`。
- 不以项目总时长要求单个 Clip 的最后时间。
- 不跨 Clip 比较前一段结束时间与后一段开始时间。

### 16.2 提示词纯净校验

阻止以下内容：

- 禁止字段和禁止短语
- 文件扩展名和本地路径
- 内部资产 ID
- Markdown 解释段、状态说明和用户说明
- 非当前 Clip 的时间码

### 16.3 续写门禁

- Clip 01 不需要上游 Actual End State。
- Clip 02 及以后必须存在上一段 `actual_end_state.json`。
- 上一段状态必须是 `end_locked` 或 `completed`。
- 缺少真实结果时，校验失败，不允许创建下一段可执行提示词。

### 16.4 连续性校验

人工与模型共同检查：

- 开场姿势是否承接上一段动作阶段
- 人物和道具是否保持屏幕方向
- 镜头是否从上一段机位合理衔接
- 光线和天气是否有可解释变化
- 声音是否有尾点、声桥或明确切断
- 相邻 Clip 是否无理由重复同一动作

## 17. 内容负载规则

每个 Clip 只承担一个主要戏剧任务，最多一个次要任务。动作数量必须与本段时长匹配。

推荐上限：

- 5 秒：一个动作或一个揭示
- 10 秒：一个动作链和一次镜头变化
- 15 秒：一个完整小节，最多一次主要转折

动作、运镜、光线变化、对白和特效不能同时堆满。优先保证关键动作清楚可见。

## 18. 异常处理

- 结果偏离计划：记录偏差，以真实结果为下一段起点。
- 结果结尾不稳定：选择最后一个稳定可续接的画面作为锁定点。
- 角色造型漂移：在下一段引用对应角色图，并从实际结尾动作继续。
- 动作提前结束：下一段不得重新表演同一动作，改为承接动作后果。
- 动作未完成：下一段从当前动作阶段继续，不从动作起点重来。
- 用户要求改写上一段：当前段进入 `needs_revision`，后续段全部失效。
- 用户停止生图或视频生成：停止媒体任务，保留文本和已完成结果，不伪造实际末帧。

## 19. Seedance 类模型适配原则

- 每个 `@` 引用都要说明用途。
- 提示词按主体、场景、动作、镜头、时间、声音和风格组织。
- 10 秒以上 Clip 使用局部时间区间表达动作进程。
- 动作、镜头和声音必须相互兼容。
- 控制内容负载，避免在短时长内堆入过多事件。
- 续写优先引用上一段实际视频及其最后稳定画面。
- 具体时长、分辨率、引用数量和音频能力在执行时查验当前平台规则。

## 20. 验收标准

### 20.1 功能验收

1. 输入一个 60 秒故事需求，系统只生成 Clip 01 的可执行提示词。
2. 未上传 Clip 01 结果时，请求 Clip 02 会停在等待状态。
3. 上传 Clip 01 后，系统生成 Actual End State，再生成 Clip 02。
4. Clip 01 和 Clip 02 的时间码都从 0 开始。
5. 纯提示词文件中不存在资产引用字段、内部资产 ID、文件名和解释性语句。
6. Clip 02 开场动作、人物位置、机位、光线和声音承接 Clip 01 的真实结尾。
7. Word 提示词页可整段复制，不需要手动删除说明文字。

### 20.2 自动测试

- 正例：两个 15 秒 Clip 各自使用 `0-15秒`。
- 反例：Clip 02 使用 `15-30秒`，校验失败。
- 反例：提示词包含 `REF-001_villager-squad.png`，校验失败。
- 反例：提示词包含“直接使用用户图 1”，校验失败。
- 反例：Clip 02 缺少 Clip 01 的 Actual End State，校验失败。
- 正例：Clip 02 使用 `@视频1最后一帧` 并有完整局部时间，校验通过。
- 正例：广告、MV、教程和剧情短片都能使用同一 Clip 闭环。

### 20.3 人工测试

- 对比真实末帧和下一段首秒，确认姿势与屏幕方向连续。
- 检查相邻 Clip 是否重复动作。
- 检查四问是否真实改变了摄影、光线和声音，而非只写成装饰词。
- 直接把纯提示词粘贴到目标模型，确认没有需要删除的制作说明。

## 21. 迁移计划

1. 重写 `SKILL.md`，将一次性全片流程替换为 Clip 闭环。
2. 重写提示词规范，删除资产调用字段和全局累计时间。
3. 重写交付质检，增加纯净提示词和续写门禁。
4. 升级初始化脚本，创建 `03_clips/CLIP-01` 结构和 Clip 元数据。
5. 升级校验器，按 Clip 验证局部时间和上游实际结果。
6. 新增提示词纯净检查。
7. 更新 README 和 Agent 默认提示。
8. 使用剧情、广告、MV、教程和世界观展示样例回归。

## 22. 发布条件

- Skill 快速校验通过。
- 初始化脚本和项目校验器测试通过。
- 所有 PRD 反例均能被阻止。
- 至少一个两段连续样例通过 Actual End State 门禁。
- README 不再宣称一次生成整部影片的全部提示词。
- 已安装 Skill 与发布仓库内容一致。
